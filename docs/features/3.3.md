**Recommendation (decision P-1): match against our own catalog first, then against a locally imported
open dataset for the pilot area. Use Overture Places as the primary source and FSQ OS Places as the
second, imported as a pilot-neighbourhood extract.**

Why:
- Storage is allowed, which a saved place needs indefinitely.
- There is no per-call cost and no runtime external call.
- Matching is deterministic and testable offline (beta build rules).
- It works with our Mapbox/MapLibre map, which Google's terms forbid.

Revisit a paid API only if open-data coverage proves too thin in the pilot (§8 metric). The Google
Places "logo plus no non-Google map" rules make it a poor fit while the app's map is Mapbox/MapLibre.

**Public photos (2.8):** none of the open datasets provides photos. The founder decision for the pilot
stands: photos are uploaded by the team or with permission. A photo provider stays undecided (decision P-6).

## 3. Matching service

### 3.1 Inputs and outputs

```
match(input: {
  text: string,               // a line from a note, a title from a link
  city: string,               // the chosen import city (pilot: Columbus)
  near?: { lat, lng },        // when the input carries coordinates (map URL)
  url?: string,               // source URL, for dedupe only (never fetched beyond permitted metadata, 3.5)
}) → { confidence: "exact" | "high" | "ambiguous" | "none", candidates: Candidate[] }   // best first, ≤ 5

Candidate = { kind: "catalog", placeId } | { kind: "external", source, externalId }
            plus name, address, neighbourhood, lat, lng, distance_m?, score
```

### 3.2 Pipeline

1. **Normalise** the text. Lowercase, strip punctuation and diacritics, and drop leading articles
   ("the", "a"). Keep the words that distinguish a place ("cafe", "bar"). Pull out a trailing "in
   <area>" or "– <area>" as a neighbourhood hint (fixture: "Fox in the Snow in Italian Village").
2. **Catalog search:** visible places in the city, ranked by trigram similarity on the normalised name.
   A hinted neighbourhood or `near` breaks ties. Only places the importing user can view (`can_view_place`).
3. **External search** (only if no catalog candidate is `exact`): the same ranking over
   `external_places` for the city.
4. **Confidence** (decision P-2):
   - `exact`: the same external id or URL dedupe key as an existing catalog place, or normalised names
     equal and within 75 m.
   - `high`: similarity ≥ 0.75, within 150 m when coordinates exist, and the next candidate at least
     0.15 lower. Without coordinates, only if it's the only candidate ≥ 0.6 in the city.
   - `ambiguous`: two or more candidates ≥ 0.45, or one between 0.45 and 0.75. This is where two
     branches of one café land; the neighbourhood is shown so the user can choose.
   - `none`: nothing ≥ 0.45.
5. **Never automatic.** Every result, `exact` included, is shown for the user to confirm in 3.4b. Nothing
   becomes a save or a public place without a confirmation.

### 3.3 Dedupe keys

- External: `(source, external_id)` unique in `external_places`, and a catalog place records the external
  ref it was created from (`places.external_source`, `places.external_id`, nullable, unique together).
- Batch: `(batch_id, normalised_line)`, so a re-import of the same text doesn't create duplicates and keeps the user's edits (3.4a).
- URL: canonical URL (scheme, host, path, without tracking parameters) per user's saves (3.5).
- Spatial near-duplicate warning (not a key): same normalised name within 75 m.

### 3.4 Unmatched text

Kept as a private draft line in the import batch (3.4a). The user can match it by hand later, or delete
it. It never becomes a place by itself.

## 4. A confident external match that is not in our catalog

Bookmarks need a FindMaxxing `place_id`. **Recommendation (decision P-3): an owner-only draft place, as a
`places` row.**

- `status = 'draft'` (new value) and `visibility = 'private'`: only the owner can see it, through the
  existing private-visibility rules. Discovery, recommendations, shares and outings never show drafts.
- Copy only factual fields from the external record (name, lat/lng, address, category hint), plus
  `external_source`/`external_id` and `origin = 'import_draft'`.
- The description check is relaxed for drafts only (a draft has no description yet). The user's
  personal aside goes to the save's private note (3.1), never into the place.
- Drafts are created by the import RPC, not the place-create path. They don't count against the
  20/day place limit; they have their own cap (decision P-4: 200 drafts per user, 50 per batch).
- **Promotion to public is a separate, deliberate flow:** "Add this to the map" opens the normal place
  form, pre-filled. Validation, moderation and the normal rate limit apply, and publishing creates the
  public state through the existing update path, with the user's explicit submit. No import, save or
  confirm action changes a draft's status or visibility.
- If a public place later matches the same external id, the draft is offered for merge (the save moves
  to the public place; the draft is deleted). Never automatic.

Required test: confirming a personal save can never publish a venue or the user's source note
(direct API calls included, and as another user).

## 5. External data storage

`external_places(source, external_id, name, norm_name, lat, lng, address, city, neighbourhood,
category_raw, release, license, imported_at)`:
- primary key `(source, external_id)`;
- trigram index on `norm_name` and a city index;
- **service-role only**, no API-role access (the matching RPC reads it).

Imported by a script (`scripts/import-open-places.ts`, built in batch 3.3-B1) from a local file the owner
downloads (§9). The script takes a bounding box for the pilot area, records the dataset release and
licence per row, and is idempotent per release.

**Attribution in the app (decision P-5):** wherever external-derived data is shown (import review, draft
place), show "Place data: © Overture Maps Foundation" or the Foursquare OS Places notice. A footer
credit is not enough on those screens.

## 6. Adapter and fakes

```
interface PlaceCandidateSource {
  id: "catalog" | "overture" | "fsq_os" | "fake";
  search(q: { norm: string; city: string; near?: LatLng; limit: number }): Promise<Candidate[]>;
}
```

- `catalog` and the open-dataset sources run in SQL. `fake` is a deterministic fixture for tests and demo
  mode.
- A future API provider would be another implementation, with no live call and no key until the owner
  decides (beta build rules).
- Demo mode carries a small fixture extract, clearly fictional and marked `origin: fictional` (0.3).

## 7. Tests (for the builds)

- The 3.4 fixture: a note with a duplicate, two branches of one café, an unknown place and a personal
  aside → duplicate merged; branches `ambiguous` with neighbourhoods; unknown kept as a draft line; the
  aside goes to the private note.
- Idempotent re-import keeps edits.
- Confidence boundaries at 0.45 / 0.6 / 0.75 and 75 m / 150 m.
- `can_view_place`: a locals-only place is never offered to a non-local.
- Drafts are invisible to other users, anon, discovery, recommendations and shares (RLS and direct API).
  A draft never becomes public without the promote flow. The draft cap applies.
- `external_places` is denied to anon and authenticated.
- Attribution is rendered on the review and draft screens.
- Demo parity with the fixture source.

## 10. Only the owner can do

- **Read and accept** the Overture data licence and, for FSQ OS Places, the Hugging Face gate form and its
  "Non-Commercial Categories" table. Then download the pilot-area extract.
- **Confirm the provider terms that could not be fetched here:** the Mapbox Search Box and Geocoding
  storage terms, and Google's current Service Specific Terms text. Allowing `www.mapbox.com`,
  `docs.mapbox.com`, `cdn.prod.website-files.com` and `operations.osmfoundation.org` in the session's
  network settings would let an agent quote them.
- If a paid provider is ever wanted: create the account, get a written storage answer (e.g. from Mapbox
  sales), and add keys. Nothing in the build needs keys.
- Run the public-photo collection with permission (2.8).
