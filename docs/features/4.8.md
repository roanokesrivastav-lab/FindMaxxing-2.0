# 4.8 Party poster event card

Built 2026-11-05 under [beta-build-rules.md](../beta-build-rules.md). Ticket: roadmap-80.md §4, M4 "4.8"
(founder decision: hosts can toggle a Party poster on events it suits; everything else uses the
Readiness row; no calendar date block). Lane B1. Flag: `pilotEvents`. Migration **0053**.

## Contract

- `events.card_style` (`readiness` default / `party_poster`), as reserved in 4.0 §5. A host-only toggle
  in EventForm ("Show it as a party poster"); off by default. When on, the event's card renders as a
  Party poster. Price, Full and Cancelled stay visible on it. Works with no photo, long titles, larger
  text and keyboard only (it is a single link).
- Off (`pilotEvents` off): no toggle, nothing written, legacy card everywhere.

## Choices recorded (recommended option taken; the roadmap asks the brief to choose the look)

- **Poster look:** typographic, photo-free by design so every poster is complete without a photo: the
  ink surface (`bg-ink`, paper text: the palette's own two ends), category with its icon, the title in
  the page-title role (Bricolage, the largest type role, clamped at four lines), then date and time in
  the item-title role, the venue, and a bottom line with Cancelled / Ended / Full, the price (or
  "Free") and the going count. No new colours, radii, shadows or sizes: tokens and type roles only.
- **Status on the poster** uses the same text + shape rule as `StatusLabel` (Ban icon + "Cancelled",
  triangle + "Full") but in paper ink, because `StatusLabel`'s tone colours (danger red, moss) fail
  contrast on the ink surface. `StatusLabel` itself is unchanged.
- **Where the poster shows:** wherever `EventCard` shows (place "Happening here", explore preview,
  rails, flag-off lists). The 1.5 Events tab keeps utility rows for every event (the tab is for
  comparing), and the event page keeps its editorial layout.
- **"Host-only":** EventForm is only reachable by the creator (create / edit own); the database
  enforces it through the column grant + RLS + owner guard, and the demo store mirrors it.
- Demo seed: "Basement show: three local bands" has the poster on (SQL seed and demo alike). See it on
  the Fourth Street Basement place page (signed in, e.g. lena).

## Test results

- `tests/event-party-poster.test.ts` 6/6: default `readiness` for every unseeded event; only the host
  can toggle (**another user, moderator, anon** change nothing); bad value refused by the check; the
  real create action (off by default, on with the toggle, ignored with the flag off); demo parity
  (non-host refused, bad value refused); the poster with a long title and no photo, Full / Cancelled /
  price visible; non-poster events keep the Readiness card; no readiness (flag off) → legacy card.
- `npm run check` with `TEST_DATABASE_URL`: exit 0 (83 files, 1,315 tests, none skipped).
- Browser (production demo build, 390×844): the poster on the Fourth Street Basement place page, and
  the form toggle. axe 0 violations, no page errors. At 200% text the place page overflows 18 px from
  the place page's own "Add best for / less suited" button (lane B2's area, not the poster); the
  poster wraps, breaking very long words. The create form's pre-existing 25 px (see 4.1) remains.
