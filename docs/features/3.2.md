# 3.2 Library tools

Built 2026-11-05, lane B2. Ticket: roadmap-80.md §4 M3 "3.2" (Mapstr: bulk edit, undo and export are required).
Flag: `pilotLibrary`. Off = today's `/saved` page. No migration (uses 0062's columns and the existing list tables).

## Contract

- **Objective:** in `/saved`: search; filter by tag, status, category; multi-select bulk edit (tag, move list, mark
  visited, remove) with undo for every action; export CSV + JSON, owner only. Rows keep what the place is apart from
  why you saved it. 500 saves stay fast (paginated).
- **Out of scope:** the picker (3.6), imports (3.4+), editing a single save's details inline (that is on the place page,
  3.1).
- **Required tests:** each bulk action and its undo; owner-only actions and export; filters with no match; 500 saves.

## Choices recorded (recommended option taken)

- **Filtering is one pure function** (`filterLibrary` in `src/lib/places/library.ts`) over `saves.library(owner)`, used
  by both repositories, so demo and Supabase agree by construction. Text search covers the place's name, neighborhood,
  city, category and interest terms, and the owner's own note, tags and recommender.
- **Filters are a plain GET form** (`?q=&tag=&status=&category=`): no script needed, reload-safe, shareable only to
  yourself (the page reads only the viewer's saves).
- **Pagination:** 50 rows render per page; "Show more" (`?page=N`, capped at 50) extends the list in place. The owner's
  saves are read once per request (fetchAllRows pages of 1,000 in Supabase).
- **Bulk actions:** mark visited, mark want to go, add a tag, remove a tag, move to a list, remove from saves. **"Move to a
  list" sets the place's lists to exactly that list** (it leaves its other lists), which is what "move" means; to add
  without leaving, the place page's save sheet still does that.
- **Undo for every action:** the bulk action returns each affected save's prior state (saved?, details, list ids); Undo
  restores it through the owner's own save, list and bookmark methods. A crafted snapshot can only change what the owner
  could already change (tested: someone else's list is skipped). **Limit:** undoing a removal re-saves the place with its
  details, tags and lists, but the saved date becomes the time of the undo (the database stamps `created_at` on insert).
- **Bulk/undo are written once** against the repository contract (`src/lib/data/libraryOps.ts`), in batches of 20. In
  Supabase that is one request per changed save; fine for a pilot library, a set-based RPC would be faster at scale.
- **Export** (`/saved/export?format=csv|json`): signed-in viewer only, no user parameter, `Cache-Control: private,
  no-store`, attachment. Columns: name, category, neighborhood, city, address, lat, lng, link, status, tags, note,
  recommended_by, source_url, lists, saved_at. CSV cells that a spreadsheet would run as formulas are prefixed with `'`.
- **Rows** use the 1.1 `Row` (photo or glyph, name, category · neighborhood · rating) for what the place is, and a
  separate block under it for status (`StatusLabel`), tags, note and recommender, marked "Only you" once above the list.
- `supabase/repository.ts`: `PlaceRow`, `PLACE_SELECT` and `mapPlace` gained `export` (no other change) so the library
  query reuses the canonical place mapping.

## Test results

- `tests/library.test.ts`: 10/10: filters (text over place and own fields, tag, status, category, bad status ignored);
  minimal bulk patches; CSV quoting, negative numbers kept, formula defused; **each of the five bulk actions changes the
  library and its undo restores it exactly** (details, tags, lists); bulk on places not in your saves and to someone
  else's list refused; crafted undo cannot touch another user's list or save; real actions (unauthenticated refused,
  summary text, undo, bad ids); export 401 signed out, another user's export lacks maya's note, CSV/JSON headers and
  content, 404 with the flag off; page renders the library, what-before-why in each row, "No saves match these filters"
  with Clear filters, tag filter; **500 saves render 50 rows with Show more in well under 3 s** (page 3 = 150 rows); flag
  off renders today's page.
- `npm run check` with `TEST_DATABASE_URL` set: **exit 0**, 81 files / 1,293 tests, none skipped, build OK.
- Browser (production demo build, 390×844, maya): `/saved` and `/saved?q=zzzz` (empty state) 200, axe 0, 0 px overflow
  at normal and 200% text, no page errors. Keyboard: Space on a row checkbox opened the bulk bar; Apply (mark visited)
  showed "Marked 1 place as visited." with Undo; the row read Visited; Undo put it back to Want to go; the CSV export
  returned 200 with the header row.
