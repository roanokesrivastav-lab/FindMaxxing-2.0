## Contract

- **Objective:** rework `src/app/places/[id]/page.tsx` photo first. The first screen leads with the place's
  photo, then name, category and neighborhood. Scrolling down: (1) one "known for" sentence; (2) price,
  travel time, hours, with unknowns said honestly; (3) the rating next to its count; (4) the most relevant
  recent observation (slot, filled by 2.6); (5) You, Friends and Community as separate blocks, never one
  score, no friend match score; (6) reviews, friends' actual reviews first, then everyone else's, each
  attributed, never summarized; (7) best for / less suited (slot, filled by 2.7); (8) one local tip on an
  Inset surface; (9) Save, Add to outing (disabled: M5 is not built), Directions. Claims open their
  evidence. The no-photo version is a complete layout.
- **Scope:** the page route, a new `PlaceDecisionPage` server component, an `Evidence` disclosure, pure
  helpers for ordering reviews and the known-for line, one additive prop on `RatingControl`.
- **Out of scope:** schema changes (none allowed), the photo model (2.8), tips (2.6), occasions (2.7),
  outings (M5), sponsored content (there is no sponsored slot on the place page today; nothing added).
- **Acceptance:** blocks in the order above at 390×844; friends' reviews before everyone else's; no text
  summarizing friends; Add to outing is a disabled button with a visible reason; each claim (rating, rating
  average, save count) opens what it is based on; with no photo the category glyph leads and every block
  is still present; with the flag off the old page renders.
- **Required tests:** the real page route rendered on the server, flag on and off, signed in and out,
  photo and no-photo, empty place, hidden place for another viewer.

## Choices recorded (owner can't be asked during a run; recommended option taken)

- **"Friends" = the people the viewer follows.** It is the viewer's own choice, already public in the follow
  graph, so marking those reviews reveals nothing new. Mutual follow would hide most reviews in a small
  pilot. The heading says "From people you follow", so the rule is visible.
- **The viewer's own review is not repeated in the lists.** It is in the You block (the rating control with
  its note).
- **Friends block:** each friend who reviewed, by name, with their own stars, linking to their review. It is
  a list of attributed reviews, not a count or an aggregate. Reviews themselves are the existing rating
  notes (`listRatings`).
- **"Known for"** is the first sentence of the contributor's own description, quoted, never generated. No
  description, no line.
- **Price and hours are not in the schema.** The page says "Not listed yet" rather than hiding the row, so the
  absence is honest. **Travel time** needs the viewer's location, which the server does not have; the row says
  "Depends on where you start: use Directions". 6.1's routing adapter could fill it later.
- **Evidence** is a native `<details>` disclosure ("What it's based on"): works by keyboard and screen reader
  with no script. The rating's evidence explains the average and links to the written reviews; the save count's
  says the total is counted and savers are private.
- **No photo:** instead of an empty hero frame, a 72px `PlaceGlyph` leads beside the name (`data-hero="glyph"`).
- **Add to outing** is a real `<button disabled>` with `aria-describedby` pointing at visible text: "Group
  outings arrive in a later update."
- **Further down** (unchanged content, restyled with 1.1 tokens): About (the full description when it is
  more than the known-for sentence), interest tags, the photo gallery, Where, Happening here, owner
  controls, report.
- **Primitives:** `Surface` (inset for You, facts and the tip; flat for Where), `SectionHeader`,
  `PlaceGlyph`, `StatusLabel`. Existing child components that still use the legacy `.card` (PlacePhotos,
  EventCard, VisibilityNotice, PlaceOwnerControls) are unchanged; restyling them is their own work.
- **`RatingControl` gets one additive prop, `hideAggregate`,** so the community average appears once (in
  the Community block, with its evidence). Default `false`: every existing use is unchanged.

## Test results

- `tests/place-page.test.ts`: 11/11. The real page module is imported and rendered with `renderToStaticMarkup`
  against an isolated demo repository (only `getViewer`, `getRepository` and the map canvas are stubbed):
  block order with a photo; friends' review (theo, followed by maya) inside the friends group and before
  marcus's in "Everyone else"; no summary wording; signed-out friends block; three evidence disclosures;
  disabled Add to outing; no-photo layout complete; empty place; private place not found for another user;
  flag off renders the old page ("What people say", no Add to outing).
- `npm run check` with `TEST_DATABASE_URL` set (local PostgreSQL 16): **exit 0**, 69 files / 1,111 tests
  passed, none skipped, build OK.
- **Browser** (production demo build, 390×844, port 3102, scratch script, not committed), Cannon & Crown and
  Meeple Cellar, signed in as maya and signed out: status 200, **0 px horizontal overflow** at normal and 200%
  root text, no page errors. The first axe run found one real defect: `StatusLabel` positive (moss) text on
  the inset surface failed contrast. The You block moved to a flat surface (it is not a tip or a note, so
  inset was the wrong role anyway); re-run: **axe 0 violations** (target-size on). After that one-class
  change the page test and lint were re-run, and the production build was rebuilt for the browser re-run.
