# 2.1 Map clustering (web)

Built 2026-11-05 under [beta-build-rules.md](../beta-build-rules.md), lane B3 (Map). Ticket: roadmap-80.md
§4, M2 "2.1", with the recorded choice: co-located records open the selected-pin preview with "1 of N"
and previous/next, never a list (the map tab is selected-pin preview only).

## Contract

- **Objective:** cluster pins at wide zooms on both Mapbox and MapLibre; a cluster tap zooms to its
  members' bounds; several records at exactly the same coordinates open the preview with "1 of N" and
  previous/next instead of zooming forever. Counts come from the full authorized matching set, labelled
  partial when the marker query is capped. Keyboard focus and reduced motion keep working.
- **Flag:** `pilotExplore`. Off: `MapCanvas` gets no `clustering` prop and draws every marker on its own,
  exactly as before (the stack handler is not passed either).
- **Out of scope:** native maps, a list of co-located records (rejected by the founder decision), 2.2 URL
  state.

## Acceptance

1. Below zoom 15 (`CLUSTER_MAX_ZOOM`), pins in the same 64 px screen cell merge into a count button.
2. Activating a cluster fits the map to its members (max zoom 18, where nothing clusters), so it ends.
3. Records at the same coordinates (to ~1 cm) always form a stack, at every zoom: a pin with a count
   badge. Activating it opens the first record's preview with "1 of N here" and Previous/Next buttons
   (disabled at the ends); the order is stable (places first, then events, then id).
4. A cluster's count is its members from the map query, which returns the whole authorized matching
   set up to its cap; when the query reports `truncated`, the count shows "N+" and the name says
   "partial count".
5. The selected pin, and the pin that has keyboard focus, are never merged into a cluster (the selection
   stays visible and distinct; focus is not lost when the map re-clusters).
6. Cluster and stack pins are native buttons whose accessible name starts with the visible count. Map
   moves use the existing `duration()`, which is 0 under reduced motion.

## Choices recorded (owner can't be asked during a run; recommended option taken)

- **Own grid clustering, no dependency.** Pins are DOM markers rendered by React for both providers;
  a small deterministic grid in `src/lib/map/cluster.ts` works identically on both, needs no new
  package, and is unit-testable. Clusters use the whole zoom level so they do not reshuffle mid-animation.
- **Stack ordering:** places first, then events, then id: stable across refreshes.
- **Counts are the loaded markers, not a second count query.** The map query already returns every
  authorized match up to `DEFAULT_MAP_MARKERS` (300) with a `truncated` flag; past that the count is
  labelled partial rather than adding per-cluster count queries.

## Test results

- `tests/map-clustering.test.ts` 12/12: merging at wide zoom with every pin exactly once; no clustering
  at close zoom; **co-located pins** stack at zoom 15 and 18 with a stable order; selection and its stack
  kept out; deterministic for any input order; bounds cover members; full vs **partial** labels; pin
  markup; through the real `/api/discover/map` route: a **capped query** (`limit=3`) is labelled partial,
  **hidden places excluded** from every cluster, real co-located demo records (an event at its place)
  stack; the page passes the flag on and off.
- **Real browser, production demo build, port 3103, 390×844 and 1280×900** (scratch script, not committed):
  6 clusters and 3 stacks at the default zoom; Enter on a cluster zoomed in until no clusters remained;
  Enter on a stack showed "1 of 2 here" with Tuttle Lot Fields, Next showed "2 of 2 here" with Sunday
  pickup soccer (desktop: Cannon & Crown, then OSU game watch party); no list inside the map; 0 px
  overflow; no page errors. axe found one real defect, fixed before commit: cluster names did not
  include the visible count (`label-content-name-mismatch`). One remaining contrast finding is
  pre-existing and not touched here: the `KindBadge` in the existing `PreviewCard`.
- `npm run check` with `TEST_DATABASE_URL` set (local PostgreSQL 16): **exit 0**. 75 files / 1,222 tests passed, none skipped, build OK.

## Could not verify / limits

- Map tiles cannot load in this sandbox (no network), so the check ran over the tile-error state; pins,
  clusters and the preview rendered above it. Mapbox was not exercised (no token); both providers share
  `MapCanvas`, so the same code path draws their markers.
- No device, touch-gesture or screen-reader pass.
- A dense area beyond 300 markers shows partial counts; per-cluster exact counts would need a server-side
  aggregate (not built).
