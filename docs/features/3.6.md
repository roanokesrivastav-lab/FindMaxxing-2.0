# 3.6 Pick somewhere from my saves (R1)

Built 2026-11-05, lane B2. Ticket: roadmap-80.md §4 M3 "3.6" (Mapstr decision). Flag: `pilotLibrary`. No migration.

## Contract

- **Objective:** on `/saved`, the user narrows their own saves with the 3.2 filters (tag, status, category, and search)
  and gets one place to go, with a way to pick again and to open it or get directions. Owner-only: reads only the
  viewer's saves and never exposes private fields. If nothing matches, say so and offer one specific widening.
- **Required tests:** empty library, one match, filters with no match, another user cannot call it for someone else.

## Choices recorded (recommended option taken)

- **Pick method: uniformly random among the matching saves, without repeats within a round.** "Pick again" never shows a
  place already shown until every match has been, then a new round starts (never with the place just shown). Random is
  honest: the app does not pretend to know best, and it needs no location, hours or opening data (none exist; see 2.5).
  Nearest-first would need the viewer's location, and "open now" has no data. The card says "Picked at random from N
  matches".
- **It uses whatever library filters are applied** (the GET form from 3.2), so narrowing is the same control. With no
  filters it picks from all saves and says so.
- **One specific widening:** drop one filter, most specific first (tag, then search, then category, then status), and
  offer the first that has matches, with its count, as a link to the widened `/saved` URL.
- **Owner-only by construction:** the action takes no user id; it reads `saves.library(viewer)`. The result carries only
  community fields (id, name, category, neighborhood, coordinates, photo URL), never note, tags or recommender.

## Test results

- `tests/pick-from-saves.test.ts`: 8/8: empty library → "empty"; one match picked for any random value; no repeats across a
  whole round, then a new round not starting with the last place; no match → one widening that does match; real action
  refuses signed-out viewers, picks only from theo's own saves over 20 tries, and returns only community fields; empty
  library and no-match answers; forbidden with the flag off; the picker renders on `/saved` with the filtered caption.
- `npm run check` with `TEST_DATABASE_URL` set: **exit 0**, 82 files / 1,301 tests, none skipped, build OK. (One earlier run
  failed `tests/auth-limits.test.ts` on a rate-window boundary, "Try again in a minute" vs "N minutes": unrelated to this
  lane, it passed alone and on the full re-run.)
- Browser (production demo build, 390×844, maya): Enter on "Pick somewhere from my saves" showed a pick; Enter again
  ("Pick again") showed a different place; axe 0; `/saved?q=zzzz` → "Nothing in your saves matches these filters" with
  "Try without the search “zzzz” (4 places)". The first browser run found a real defect: the button used `loading`, which
  disables it, so keyboard focus dropped after each pick. It now stays enabled with `aria-busy` and ignores double
  presses; pick tests, lint, typecheck and a production build were re-run after that change.
