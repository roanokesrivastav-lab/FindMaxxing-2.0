# 2.7 Best for / less suitable for

Built 2026-11-05, lane B2. Ticket: roadmap-80.md §4 M2 "2.7"; owner answer 2026-11-05 (stays, written and attributed
by contributors; never summarize what friends think). Flag: `pilotExplore` (slot 7 of the 2.5 page). Migration:

## Contract

- **Objective:** contributors add short attributed occasion notes ("Good for a relaxed date", "Less suited for a big
  group") picked from a small occasion list plus optional free text. Multiple opinions coexist; the page shows the top
  one or two per side with attribution and "see all". No AI-invented experience.
- **Out of scope:** a moderator screen (moderators hide through the repository or SQL), reports on notes, filtering
  places by occasion.
- **Required tests:** RLS (anon, author, another user, moderator), moderation hide, demo parity, real action and page.

## Choices recorded (recommended option taken)

- **Occasion list (8):** a relaxed date, a big group, talking over a drink, working solo, bringing kids, a quick bite,
  late night, a first visit to the area. Kept in a check constraint and `src/lib/places/occasions.ts`.
- **One note per author, place, occasion and side.** Adding again updates the note text (an author can say a place is
  both good and less suited for one occasion, e.g. "date" on and off game nights, as two notes).
- **Free text** is optional, at most 140 characters.
- **Shown:** two per side ("Best for", "Less suited for"), then a native "See all N" disclosure. Order: notes by people the
  viewer follows first, each as their own attributed note, then newest. No counts per occasion, no percentages.
- **Status is moderator-only** (trigger); hidden notes are visible only to their author and moderators.
- **Rate limit:** `occasion_notes`, 30/day (SQL rule + `src/lib/rateLimits.ts`).
- **Demo:** lazy collection (`src/lib/data/demo/occasions.ts`), seeded with the same three notes as the SQL seed
  (`SEED_OCCASION_NOTES`) so demo mode shows the block on Cannon & Crown and Meeple Cellar.
