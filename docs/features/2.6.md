# 2.6 Tip provenance and freshness

Built 2026-11-05, lane B2. Ticket: roadmap-80.md §4 M2 "2.6". Flag: `pilotExplore` (the tips UI and actions
live on the 2.5 page; with the flag off nothing user-facing changes). Migration: `0060_place_tips.sql`.

## Contract

- **Objective:** local tips get an author, `created_at`, `last_confirmed_at`, `last_confirmed_by`, and a kind:
  lasting story / practical tip / temporary condition (temporary needs `expires_at`). "Still true?" confirms;
  "Suggest a correction" records an attributed suggestion. An edit is not a confirmation. Display "Confirmed by
  Maya, 2 weeks ago"; the claim opens the evidence (the tip, who confirmed it and when, corrections). Supply
  2.5's most relevant recent observation. Rate-limit confirmations.
- **Out of scope:** a moderator queue UI for tips (moderators can hide via the repository / database; no
  screen added), reports on tips, notifications.
- **Required tests:** RLS as anon, author, another user, moderator; expiry hiding; self-confirmation not counting;
  the evidence view respecting hidden or removed tips; rate limit; demo parity; the real action and page path.

## Choices recorded (recommended option taken)

- **Tips are their own table; `places.local_tip` stays** (the place form still edits it). Existing tips are copied
  once as *practical* tips by the place's creator, unconfirmed. The SQL seed applies the same copy (it inserts
  places after migrations) and the demo store mirrors it lazily. If a place has no tip rows but a legacy
  `local_tip` (written after the migration through the old form), the page shows it labelled "From the person who
  added this place, not yet confirmed".
- **Confirmations are an append-only table**; the tip's `last_confirmed_*` is kept by a definer trigger. Clients
  have no UPDATE grant on those columns, and the edit trigger restores them, so an edit can never move them. The
  same person may confirm again later (it re-dates the tip), limited by the `tip_confirmations` rate limit
  (60/day). Confirmation time is server time (client `created_at` is overwritten).
- **Self-confirmation is refused** (database trigger and both repositories), not silently ignored.
- **Status is moderator-only** (trigger), so an author cannot un-hide a moderated tip. Hidden/removed tips, their
  confirmations and corrections are visible only to the author and moderators (`can_view_place_tip`).
- **Expiry is a display rule:** "current" = published and not expired. Discovery and the page show only current tips;
  an expired tip remains evidence for its author and moderators. Temporary conditions run at most 90 days.
- **Recent observation** = a current tip confirmed by someone other than its author within the last 180 days, most
  recently confirmed first, with the confirmation date shown. An unconfirmed tip is never "an observation".
- **Rate limits:** new rules `tips` (20/day, tips and corrections) and `tip_confirmations` (60/day), in
  `rate_limit_rules` and `src/lib/rateLimits.ts` (the existing equality test covers both).
- **Demo collections are created lazily** (`src/lib/data/demo/tips.ts`, `ensureTips`) rather than with a store
  version bump, so this lane does not collide with other lanes' `STATE_VERSION` changes. Old store files gain them in
  place on first use. Account deletion in demo mirrors the SQL foreign keys (`placeExtras.ts`).
- **Seeded confirmations** (`src/lib/places/tipSeed.ts`): maya confirms Cannon & Crown's tip, jules Meeple Cellar's,
  theo Tuttle Lot Fields', so demo mode shows a confirmed observation.

  write of confirmation columns → permission denied; non-author edit affects 0 rows; expiry check constraint both

  author; confirmations cannot be deleted; rate limit; suspended account refused. Demo: same rules, expiry hiding, parity

  (The first run failed lint on `Date.now()` in the page render (react-hooks/purity); moved into `requestNow()`.)
