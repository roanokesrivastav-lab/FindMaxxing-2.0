# 6.1 Routing adapter

Built 2026-11-05 under [beta-build-rules.md](../beta-build-rules.md). Ticket: roadmap-80.md §4, M6 "6.1".
Design: [6.0 SPEC](6.0.md) §2, §3 and §9, with decisions R-1 to R-6 accepted. Built after 6.2 (the
lane order), so its tests also drive real router output into the 6.2 validator.

## Contract

- **Objective:** a walking-only `WalkingRouter` adapter: a deterministic fake with fixtures (river
  barrier with bridges, an island with no route), a Mapbox walking client that stays off without a key
  and is never called in tests, a GraphHopper foot stub, per-request and per-plan timeouts that turn
  slowness into `unknown`, and a per-request memo. Persist no provider durations, distances or geometry.
- **Out of scope:** planner integration, removing the planner's `drivingMinutes`, the persisted
  itinerary and its RPC (all 6.3); UI; migrations; dependencies.
- **Required tests (6.0 §8):** fake contract (barrier, island, rounding); `not_configured` behaviour;
  the memo does not persist across requests; no write path receives provider fields; no real network.

## User-facing surface and flag

**None.** No route, action, page or planner tool calls the router yet; 6.3 does. The only switch is
in `selectWalkingRouter()`: a real provider runs only when the **`pilotItinerary`** flag is on **and**
its server-only key is set. Neither is set anywhere in this build.

## Choices recorded (owner can't be asked during a run; recommended option taken)

- **R-1 router selection** (`selectWalkingRouter(env, mode)`): with `pilotItinerary` on,
  `WALKING_ROUTER` (default `mapbox-walking`, or `graphhopper-foot`) plus its key
  (`MAPBOX_ROUTING_TOKEN`, `GRAPHHOPPER_URL`) picks the real provider. Otherwise the fake in demo mode,
  and an all-`not_configured` router in Supabase mode, so nothing claims a plan fits there.
  `MAPBOX_ROUTING_TOKEN` is a new **server-only** variable, deliberately separate from the public map
  token `NEXT_PUBLIC_MAPBOX_TOKEN` (documented, empty, in `.env.example`).
- **Mapbox client** uses plain `fetch` (no dependency), requests `overview=false&steps=false` (durations
  and distances only, no geometry), at most 25 coordinates per request (chunks share their boundary
  point), maps HTTP 422 and `NoRoute`/`NoSegment` to `no_route`, everything else odd to
  `provider_error`, an abort to `timeout`. It never logs the URL (it carries the token) or the response.
- **Timeouts:** 4 s per request (`withRequestTimeout`, used by the Mapbox client per chunk) and 8 s per
  plan validation (`routeLegs`), no retries. `routeLegs` never throws: a router that ignores its abort
  signal still yields `timeout` at 8 s; a throwing or malformed router yields `provider_error`.
- **R-2 caching:** `createRequestMemo()` is an in-memory memo the caller creates for one server request;
  identical legs are not requested twice within it. No module-level cache exists (a source check
  enforces it). Nothing is written to the database, the demo store, logs or a shared cache.
- **R-2 persistence:** the routing modules have no write path at all (source check). What 6.3 may store
  is defined by 6.2's `storedVerdict()` allow-list, which drops every provider number; a test routes a
  Mapbox-shaped response through the validator and checks the stored verdict carries none of it.
- **GraphHopper foot** is the named fallback as a stub: it returns `not_configured` for every leg until
  the owner chooses it and provides hosting.
- **Fake fixtures** are simplified shapes near the Columbus demo data, not real geography: a river
  polyline with two bridges and a 150 m island.

## Deferred, with reason

- **R-3 durable route-validation limit (60 per user per hour).** The 0040 limiter's budgets live in the
  SQL table `server_abuse_budgets`, so a new action needs a migration, and this lane has none. Nothing
  can reach the router yet (no route, action or planner tool), so there is no quota to protect. It moves
  to **6.3**, which adds the first caller and has a Trips-block migration (0095–0099): add the
  `route_validation` action there, keyed by user id, and call it before `routeLegs`.
- **Removing `drivingMinutes` from the planner's `distance` tool** (6.0 §3/§6) is planner integration:
  6.3.

## Test results

- `tests/walking-router.test.ts`: **20/20 passed.** `globalThis.fetch` is replaced by a spy for the
  whole file and `afterAll` asserts it was **never called**; only the Mapbox URL builder and response
  parser (pure) are exercised. The test process has no routing keys, and its default selection is the
  fake.
  - Fake: 1,336 m → 17 minutes (rounded up); a river crossing detours over the nearest bridge
    (1,193 m straight becomes 3,980 m / 50 minutes); the island has no route either way; deterministic.
  - End to end into 6.2: the old planner's straight-line estimate says the east-bank reservation fits;
    the router's detour reaches 6 p.m. at 6:20 → `fixed_start_missed` (or `leg_over_max` at the default
    30-minute limit); the island stop → `uncertain`; a hanging provider times out at exactly 8 s (fake
    timers), aborts its signal, makes the plan `uncertain`, and the last saved verdict stays on show
    marked possibly outdated.
  - `routeLegs` never throws (throwing, sync-throwing, wrong-count and negative-duration routers give
    `provider_error`; a cancelled validation gives `timeout`); the per-request timeout fires at 4 s.
  - Memo: no repeat within one request; a second request's memo starts empty.
  - Selection: fake in demo, `not_configured` in Supabase (and the validator then says `uncertain`); a
    key without the flag (or with `all`) never selects Mapbox; flag + key constructs the client without
    calling it; GraphHopper selection and its `not_configured` stub.
  - Source check: no routing module imports the data layer, the demo store or Supabase, logs, or holds a
    module-level cache; a Mapbox-shaped result leaves no provider number in the stored verdict.
- `tests/itinerary-validator.test.ts` (6.2): still 31/31.
- `npm run check` with `TEST_DATABASE_URL` set (local PostgreSQL 16): **exit 0**. Typecheck, lint,
  **70 files / 1,151 tests passed, none skipped**, build OK.

## What could not be verified

- **The Mapbox client has never run against Mapbox**: no key, no network, by rule. Its request shape
  and response handling follow Mapbox's public Directions documentation from memory and were not
  checked against a live response; error codes other than `Ok`/`NoRoute`/`NoSegment`/422 are treated
  as `provider_error`. A staging run with a real key must confirm it, and the owner must confirm the
  storage clause (6.0 §11) before any key is added.
- Whether Mapbox requires its results to be shown on a Mapbox map (6.0 §2) is unverified.
- Timeouts were tested with fake timers, not a slow real network.
