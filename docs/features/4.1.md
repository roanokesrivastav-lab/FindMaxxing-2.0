# 4.1 Event page hierarchy

Built 2026-11-05 under [beta-build-rules.md](../beta-build-rules.md). Ticket: roadmap-80.md §4, M4 "4.1"
(founder decision: opening an event shows the Local editorial treatment). Lane B1. Flag: `pilotEvents`.

## Contract

- **Objective:** behind `pilotEvents`, `/events/[id]` renders in the Local editorial treatment in this
  order: what it is → date, time and time zone as plain text (no calendar date block) → meeting point
  and travel → host and permitted social proof → cost and availability → requirements → status + one
  primary action. A **"Your first time?"** block (meeting spot, who welcomes you, what to bring, solo
  welcome) comes from host-entered fields. Fix "Free to join" showing above a paid ticket action.
- **Status labels** use `StatusLabel` (text + shape). This ticket has Going / Full / Cancelled / Ended;
  Interested and Waitlisted arrive with 4.4 through the page's `status` slot. **Awaiting approval** is
  not built: there is no approval flow in the product, and adding one would be new scope.
- **Migration 0050** (`events.newcomer jsonb`) — the only schema change, as the ticket allows.
- **Off = today's page**, with one deliberate exception: the copy bug fix (below).

## Choices recorded (recommended option taken)

- **Newcomer storage:** one nullable `jsonb` column with a database shape check
  (`valid_event_newcomer`, keys `meetingSpot` ≤ 140, `welcomer` ≤ 80, `bring` ≤ 200, `soloWelcome`
  boolean), mirrored by `eventNewcomerSchema` in `packages/shared/src/events.ts` and the demo store.
  Written by the creator through a **column grant** (`grant update (newcomer)`), so the existing RLS
  update policy and `guard_owner_event_change()` still decide who and when. No new definer function,
  so the function-grant allowlist is unchanged.
- **Copy fix on the flag-off page too.** The ticket names it as a bug ("free to join" above a paid
  ticket action). It is a one-line copy change: a priced event now says "Get a ticket to join." This
  is the only flag-off change in the lane so far, recorded here on purpose.
- **Photography-led without event photos:** events have no photo field, so the linked place's lead
  photo leads when it has one; otherwise the category glyph sits beside the category label and the
  page is complete without a photo.
- **Time zone:** the viewer's zone with its label ("10:00 AM – 12:00 PM EST"), as today. 4.2 adds
  `events.time_zone` and switches display to the event's own zone.
- **Primary action** sits in a raised bar that floats above the tab bar (raised = the floating role),
  so status and the one action are always reachable at 390×844. Join/ticket buttons keep their
  existing names ("Join event", "You're going"), which the e2e suite uses.
- **Requirements** section is a slot left out when empty; 4.2 fills it with activity details.

## Test results

- `tests/event-page-editorial.test.ts` 13/13:
  - shared schema (trim, empty → null, unknown keys, lengths);
  - PGlite: the owner sets it; **another user, a moderator and anon** change nothing; anon can read it
    on a visible event; past events refused; the check refuses unknown keys, wrong types, long text,
    non-objects;
  - demo parity: stored / unchanged on undefined / cleared on null / bad shape refused / non-owner refused;
  - **real actions** on the demo repository: saved with the flag on, field error for over-long text,
    ignored entirely with the flag off;
  - **real page**: editorial order (h1 → When → Meeting point → Host → Cost → action), zone label, no
    first-time block when empty, the block when set, a paid event never says Free (flag on and off;
    off now says "Get a ticket to join."), and flag off renders today's page.
- `npm run check` with `TEST_DATABASE_URL` set: exit 0 (71 files, 1,159 tests, none skipped). The first
  attempt hit a worker SIGKILL / timeout from machine load (four lanes on 4 cores); the re-run passed
  unchanged.
- Browser, production demo build, 390×844, 100% and 200% text: event page anonymous, as a non-attendee
  and as the host; the create form signed in. HTTP 200, no page errors, **axe 0 violations**, 0 px
  overflow on the event page. The create form at 200% overflows by 25 px from the existing
  date/start/end three-column grid's "optional" hint (`FieldLabel`), which predates this ticket and is
  not in the new section; recorded, not changed here (the form layout is not this ticket's scope).
