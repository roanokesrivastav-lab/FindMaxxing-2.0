## Contract

- **Objective:** the event page in the Local editorial treatment, in one reading order: what it is →
  date, time and time zone as text → meeting point and directions → host and who is going → cost and
  spots → what to expect → status and one honest action. A priced event never says "free". A full
  event says Full and offers no queue.
- **Allowed files:** `src/app/events/[id]/page.tsx`, a pure helper for the wording rules, one CSS
  class, tests and a browser script. No migration, no repository change, no new dependency or flag.
- **Prerequisites verified:** 1.1 primitives present; 4.2 and 4.3 reverified in batch 00. The Codex
  review of 2026-11-12 cleared "the existing-contract UI portion of 4.1" to proceed while the
  amendments are revised.
- **Out of scope here:** newcomer fields (below); Party poster (4.8); series, follow and
  material-change notifications (4.5a, 4.5b, 4.6); waitlists, offers and "Interested" (4.4, Later);
  the social context line (1.4, Later); native.
- **Preflight:** not required for this part. No schema, permission, payment or privacy contract
  changes; the page reads the same data through the same repository calls as before.

## Changes

- **Reading order and treatment** (`src/app/events/[id]/page.tsx`). The full-colour hero and the
  stack of cards are gone. One column on paper, one left edge, role surfaces only where they mean
  something: the action is the one Raised surface, activity details sit on an Inset one. Sections
  carry `data-part` in order: `what`, `when`, `where`, `host`, `cost`, `expect`, `action`.
- **When.** The date and the time range are plain text in the **event's own time zone**, always
  named ("Saturday, January 16" / "6:30 PM – 8:00 PM EST"). When the reader's clock reads
  differently, a second line gives "Your time". Before, the page showed the reader's zone only, and
  the share text used the city default. No calendar date block.
- **Cost and spots** (`src/lib/events/detail.ts`, pure). "Free" or "$15.00 per ticket", then
  "N going · X of Y spots left" or "Full". No spots number when the host set no limit. Held seats
  count through `events_readiness`, with the going count as the fallback.
- **Paid events never say free.** The old line "Free to join. Just show up." appeared whenever the
  viewer was not on the list, including above a Buy ticket button. It is removed. The price is now
  shown whenever the event has one, **also when the payments flag is off**; before, that case showed
  a free-looking Join button that the server would refuse. Now it says tickets cannot be bought here
  and offers no action.
- **One honest action.** Buy ticket, Join, or the going/leave toggle; none when the event is over or
  cancelled for someone who was not on it. Full: the status reads Full, the button is off, and the
  note says a spot opens if someone leaves. Nothing mentions a waitlist, an offer or "notify me".
- **The action stays in reach.** It sits in its place in the reading order and rides at the foot of
  the screen (above the navigation) until the reader gets there (`.action-dock` in `globals.css`).
  Two things found by the browser checks and fixed:
  - controls focused behind the docked block were covered by it; everything above it now has a
    scroll margin, so focus scrolls clear;
  - at 200% text on a phone the docked block covered half the page. When the screen is narrow for
    the text (under 19rem, a phone at about 130% text or more) it no longer docks and simply stays
    in its place.
- **Readiness row** (4.3, pilot flag) no longer repeats the going and spots counts that "Cost and
  spots" already gives; it shows the rest (more needed, confirm-by, venue not confirmed, It's on).
- **Tests and scripts:** `tests/event-detail.test.ts` (new), `scripts/e2e-event-detail.mjs` (new,
  `npm run e2e:event-detail`, added to CI after the onboarding step; run locally only so far).

Migrations: none. Dependencies: none. Flags: none added. Demo and Supabase: the page and helper are
shared code over the same repository interface; nothing mode-specific changed.

## Not built: "Your first time?" (blocked)

The roadmap asks for a block near Join from host-entered fields: meeting spot, who welcomes you,
what to bring, solo welcome. No such fields exist. `activity_details` cannot hold them (it requires
an activity kind and its shapes are strict), so they need a column and a new parameter on
`create_event_with_details` / `update_event_with_tags`. That is event-lane schema work, which is
held until the 4.0 amendment's second preflight. Proposed for that review, not yet a contract:

- `events.newcomer_details jsonb`, null when the host gave none; keys `meetingSpot` (≤ 140),
  `welcomedBy` (≤ 80), `bring` (≤ 140), `soloWelcome` (boolean); a database check on type and size
  like `valid_activity_details`, with the exact shape in `packages/shared`;
- public to anyone who can see the event; no names of people other than what the host types;
- shown as an Inset block directly above the action, under "What to expect"; nothing shown when empty;
- demo twin and native type updated in the same ticket.

The page already has the place for it: the comment at section 6.

## Adversarial review

- **A cancelled event and strangers.** Only people who were on it can still open a cancelled event;
  everyone else gets not-found. Unchanged, and now tested, so the new page cannot widen it.
- **Price with payments off.** Found while writing the rules: the old page hid the price and showed
  Join. Fixed as described; tested at the page level.
- **Held seats.** A seat being paid for counts as taken on the page (readiness), so the page does
  not show a spot the server would refuse.
- **Time zone.** The event's zone is whatever the host's browser was in when they made it (4.2's
  choice). The page now names it, which makes a wrong zone visible instead of silently shifting.
- **The mini map's own controls.** Its pin and attribution toggle are keyboard stops that do nothing
  useful on this page, and the attribution control redraws while tiles load. Both are older than
  this ticket and belong to the map component; the keyboard walk skips the attribution control and
  says so.
- **Private data.** The page shows what it showed before: public attendee names, the host, the
  venue. Nothing new is read.
