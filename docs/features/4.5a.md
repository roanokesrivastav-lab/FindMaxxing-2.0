# 4.5a Recurring series: model and host tools

Built 2026-11-05 under [beta-build-rules.md](../beta-build-rules.md). Ticket: roadmap-80.md §4, M4 "4.5a",
batch 4.5a of the approved [4.0 spec](4.0.md) (§3, §4, §8, §10, §14, §15 case 8). Lane B1. Flag:
`pilotEvents` (UI). Migration **0055**. Built only after 4.4's hard gate passed.

## Contract

- `event_series` (template + weekly rule + IANA zone + status + `rule_version`), `event_series_tags`,
  `event_series_hosts` (owner + backups), `event_series_followers`; occurrences are rows in `events`
  (D-A) with `series_id`, `series_local_date` (unique per series), `overridden`.
  `event_attendees.attended` for history (set by a host after the end; never inferred).
- `generate_series_occurrences(p_series, p_now)`: 4-week horizon (D-C), idempotent on
  `(series_id, series_local_date)`, never recreates a date in any status, never past `ends_on`, never
  while paused/ended/removed. Runs on create, on edit-future, and in the 15-minute notifications job.
- Host tools (RPCs, re-checking hosting on every call): `create_series`, `update_occurrence` (edit this;
  records overridden fields), `update_series_from` (edit this and future; skips overridden fields;
  schedule changes bump `rule_version`, delete empty future occurrences and regenerate, move occupied
  ones in place: same id, date, attendees, tickets, chat, new time), `cancel_occurrence`, `end_series`,
  `set_series_host` (owner only), `follow_series` (updates only), `set_attended`, `moderate_series`
  (D-J). Backup hosts also confirm sessions and see/manage the waitlist (`confirm_session`,
  `host_remove_participant`, participant RLS via `viewer_hosts_event`).
- DST (§10, D-G): `local_to_instant` resolves the spring gap to the same clock reading in the earlier
  offset and the fall-back repeat to the **first** instant, matching the app's `zonedTimeToUtc`, with a
  shared vector list tested on both.
- UI (pilotEvents): "Repeats every week" (days, every N weeks, until) on the create form; on a series
  occurrence's edit page "This event only / This and future events" (days and interval for future);
  on the occurrence page, host tools: Edit this or future, Cancel this one, End series.

## Choices recorded (recommended option taken)

- **The owner is not auto-going on generated occurrences** (a one-off creator is). Generated rows are
  the system's; the owner joins like anyone. It also keeps "empty occurrence" meaning nobody involved.
- **"Moved in place"** keeps the occurrence's local date and applies the new start time and duration;
  if its weekday is no longer in the rule it stays on its date (people already planned around it).
  Empty future dates are replaced by the new rule's dates.
- **Chat rows** in "nobody involved" means messages in the occurrence's group chat.
- **Rate limit:** creating a series counts once against the daily event limit; generated occurrences
  don't each count (they are written with no request subject).
- **Backup-host writes** run the existing owner guard as the occurrence's creator inside the definer
  RPC (after `is_event_host` passed), so the guard's other rules (future, published, capacity floor)
  still apply. A backup host's direct table update is still refused.
- **D-J moderation:** `moderate_series(series, remove)` (moderators only) marks the series and its
  future published occurrences `removed`, and restores both. No report target type "series" was added
  (reports stay on occurrences); not written to the moderation audit table (recorded limit).
- **Edit this (scope "this")** changes the core fields (title, description, venue, time, capacity) and
  records overrides; the pilot fields (newcomer, activity, session rules) are not part of the
  occurrence RPC. Tags and category follow the series.
- **Demo store:** series live in optional collections created on first use (no `STATE_VERSION` bump).

  `[race] case 8: 10 rounds × 3 series, two generators at once → 870 occurrences created, 0 duplicate local dates`.

  5 DST vectors (NY spring gap 07:30Z, NY fall-back first instant 05:30Z, 19:00 before/after the change,
  Berlin fall-back); 4-week horizon, 19:00 local, idempotent, `ends_on`; interval + weekdays (SQL dates
  = demo dates); DST occurrences across the change; cancel one Thursday leaves the next and is never
  recreated; edit this records `overridden`, edit future skips it and leaves earlier ones; schedule
  change deletes the empty one, moves the occupied one in place (id, date, attendee kept, new time),
  `rule_version` 2; backup host via RPCs, owner-only host management, **revoked host denied at once**;
  follow never creates attendee/participant rows; end series cancels later dates and stops generation;
  **RLS as anon / owner / another user / moderator**, no direct writes, D-J cascade and restore;
  attendance only by a host and only after the end; demo parity on the same operations; the **real
  create action** with "Repeats every week".
- `npm run check` with `TEST_DATABASE_URL`: exit 0 (91 files, 1,403 tests, none skipped).
- Browser (390×844): create form with Repeats open (7 day boxes); axe 0, no errors; the form's
  pre-existing 25 px at 200% remains.
