# 1.3 First-map arrival

Built 2026-11-05 under [beta-build-rules.md](../beta-build-rules.md), lane B3 (Map). Ticket: roadmap-80.md
§4, M1 "1.3". Needs 1.2 (merged on this lane).

## Contract

- **Objective:** on the first Explore visit after onboarding, the picked interests show on the map tab as
  removable filters with "Show everything" beside them. An interest with no results in the area says so
  and offers one specific widening: a bigger area when that would find something, otherwise all
  interests. Filters are never relaxed without the viewer choosing it.
- **Flag:** `pilotFoundation`. Off: today's Explore exactly (the list-panel welcome note only).
- **Out of scope:** 1.4 (on hold; no social line), the list view, 2.x map work.

## Acceptance

1. `/?tags=…&welcome=1` for a signed-in viewer with the flag on renders the arrival bar over the map (a
   Raised surface, the "floating over the map" role) with one removable chip per interest and "Show
   everything".
2. Per-interest counts come from the repositories' `count()` with the map's own filters (bounds, tag,
   category, kind, viewer), so they cover the full authorized matching set and never a capped page.
3. An interest with zero here: "Nothing for X in this area yet." plus exactly one action: "Look in a
   bigger area" (if 3× the span around the same center has matches; it moves the map there) or "Show
   all interests" (clears the interest filters). If every picked interest is empty, one combined line.
4. Counts are re-asked whenever the area or filters settle (`/api/discover/presence`), with loading and
   error states; searching hides the bar.
5. Removing the last chip, or "Show everything", ends the arrival state.
6. Location denied: nothing depends on location; the counts describe the area on screen.
7. With the flag on, Explore's interest filter also stops at the map's 8 and says so, instead of the
   discovery query dropping extras silently (part of "never silently relax filters").

## Choices recorded (owner can't be asked during a run; recommended option taken)

- **"A bigger area" is 3× the current span**, same center (`WIDER_FACTOR`). It is offered only when that
  area actually has matches, so the offer is never empty.
- **One combined line when everything is empty**, to avoid a wall of identical notices.
- **A new read-only route** `GET /api/discover/presence` (counts only, no records; 404 when the flag is
  off), reusing the discovery request parser, so the client can keep counts honest after the map moves.

## Test results

- `tests/first-map-arrival.test.ts` 15/15: bigger-area geometry; counts equal the repositories' place +
  event counts; **no matches** here but some in a bigger area offers the bigger area; none nearby offers
  all interests; hidden places are not counted; the real presence route (counts, `kind`, unknown tags
  dropped, 400 on a bad bbox, 404 with the flag off); the real Explore page (arrival with counts on the
  welcome visit, **all interests** at the 8 cap, nothing without welcome / interests / sign-in / flag);
  the bar rendered (removable chips, Show everything, one widening per empty interest, the combined line,
  loading and error).
- **Real browser, production demo build, 390×844, port 3103, geolocation denied** (scratch script, not
  committed): new account picked Coffee + Hiking in onboarding; the map showed both as removable chips plus
  "Show everything", and "Nothing for Hiking in this area yet. Show all interests" (no Hiking data in the
  demo area). Removing Hiking left Coffee and cleared the notice; "Show everything" removed the bar.
  0 px overflow, no page errors. axe: the first run flagged a label/content mismatch on the chips
  (`aria-label` hid the visible text), fixed with visible text plus screen-reader-only words. One
  remaining finding is pre-existing and not touched here: the signed-in avatar link "Your profile"
  (`label-content-name-mismatch`). Map tiles do not load in this sandbox (no network); pins and overlays did.
- `npm run check` with `TEST_DATABASE_URL` set (local PostgreSQL 16): **exit 0**. 71 files / 1,164 tests
  passed (includes other lanes' merged work), none skipped, build OK.

## Could not verify / limits

- No device or screen-reader pass.
- Demo data has no Hiking records for a new user (one of the six featured interests), so the demo shows
  the "Show all interests" path whenever Hiking is picked. Real pilot data should cover all six.
- The arrival state is not remembered across reloads beyond the `welcome=1` URL; 2.2 adds URL state.
