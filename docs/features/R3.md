# R3 Lightweight clubs

Built 2026-11-05 under [beta-build-rules.md](../beta-build-rules.md). Ticket: roadmap-80.md §4 "R3"
(stub: "a named group around one or more recurring series: members, hosts, a shared page and the existing
group chat. Joining a club never RSVPs. Spec must define membership, privacy, moderation, and how it
differs from following a series"). Lane B1. Flag: `pilotEvents`. Migration **0056**. Needs 4.5a, 4.5b.

## Spec (written first; recommended option taken for every open point)

### Contract

- **Club** = name, description, owner, status (`active` / `removed`), and one or more **series** it
  gathers. Only someone who hosts a series (owner or backup) can attach it to a club they own.
- **Membership** is open: anyone who can see the club can join or leave. Roles: `owner` (created it),
  `host` (every host of an attached series is shown as a club host, derived, not stored), `member`.
  The owner can remove a member.
- **Joining never RSVPs**: no `event_attendees` or `event_participants` row is created by joining, and
  no notification preference changes. Same rule as following a series (4.0 §3).
- **Privacy (who sees members):** recommended option **members-only**: the member list (names) is
  visible to members and club hosts; everyone else sees the club, its hosts and the member **count**.
  Host names stay public, as event and series hosts are today.
- **Visibility of the club itself:** visible to anyone, unless removed by a moderator (then only its
  owner sees it, marked removed). Attached series still follow their own visibility.
- **Moderation:** moderators can remove or restore a club (`moderate_club`). Removing a club does not
  touch its series (series moderation is D-J, 4.5a). No new report target type in this ticket (reports
  stay on occurrences and profiles); recorded as a follow-up.
- **"The existing group chat":** recommended option **no new chat type**. The club page links to the
  next session's existing event group chat, which members who are going already belong to
  (`0020_messaging.sql`). A standing club chat would need a new conversation kind and its own
  membership/privacy rules: out of scope for a lightweight club, recorded as a follow-up.
- **How it differs from following a series:** following = updates about one series (schedule changes,
  cancellations; 4.6). A club = a named, shared page across several series with a member list and
  hosts. Joining a club does **not** follow its series automatically (each stays a separate choice), so
  nobody receives notifications they did not ask for.

### Acceptance

1. A series host creates a club around a series they host; others cannot attach a series they don't host.
2. Anyone who can see the club joins and leaves; joining creates no attendee/participant rows.
3. Members and hosts see member names; non-members see only the count; anon sees the club and count.
4. The owner removes a member; nobody else can.
5. A moderator removes / restores the club; non-moderators cannot.
6. `/clubs/[id]` (pilotEvents): name, description, series with their next session, hosts, members
   (per privacy), Join/Leave, the next session's group chat link for members going. Loading, empty and
   error states; 390×844; keyboard only.
7. Demo twin at parity; RLS tested as anon, owner, member, another user, moderator.
