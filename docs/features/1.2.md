# 1.2 Interest picker rewrite

Built 2026-11-05 under [beta-build-rules.md](../beta-build-rules.md), lane B3 (Map). Ticket: roadmap-80.md
§4, M1 "1.2", with the owner answer of 2026-11-05: thumbnail rows, six interests, "More interests", Skip.

## Contract

- **Objective:** the onboarding Interests step asks "What would you go out for?" with six recognizable
  interests as text rows with a small thumbnail (PlaceGlyph, since no interest has an image), a visible
  checkmark state, a "More interests" control that reveals the rest, a visible Skip, no minimum, and a
  forward button that says "Continue". Whatever the user picks is what the first map honours.
- **Flag:** `pilotFoundation`. Off: the chip picker, "Next", and the 12-interest allowance exactly as before.
  On (demo, tests): the new picker.
- **The mismatch fix (recorded choice):** the map's discovery query takes at most 8 interests
  (`discoveryQuerySchema.tags`, shared). Raising that cap would change behaviour with the flag off, so
  the picker is capped at the same 8 (`MAP_INTEREST_LIMIT`, one constant used by the picker, the
  hand-off to the map and the Explore page). The step says the limit up front, and says so again when it
  is reached. A returning user whose profile already holds more than 8 (the profile form still allows
  12) is told which 8 the map starts with, by name. A test pins the constant to the shared schema cap.
- **Out of scope:** 1.3 (first-map arrival), 1.4 (on hold: no social context line, the People step is
  untouched), the profile form's 12-interest limit, native onboarding.

## Acceptance

1. Flag on: heading "What would you go out for?"; six rows (Pickup games, Coffee, Food, Hiking,
   Nightlife, Music), each a button with a PlaceGlyph thumbnail, its label, and a check shape that is
   filled when picked (not colour alone; `aria-pressed` for assistive tech).
2. "More interests" (`aria-expanded`) reveals every other interest; a picked interest outside the six
   stays visible even while collapsed, so nothing picked is ever hidden.
3. Zero picks is fine: "Continue" saves an empty list and moves on; "Skip" moves on without saving.
4. At 8 picks the other rows stop accepting picks and a status line says why; unpicking frees a slot.
5. The map hand-off carries exactly the picked interests (at most 8), and Explore keeps all of them.
6. Keyboard only: every row, More interests, Skip and Continue are native buttons in DOM order with a
   visible focus ring.
7. Flag off: today's chip picker and "Next" render unchanged.

## Choices recorded (owner can't be asked during a run; recommended option taken)

- **The six:** Pickup games (the milestone journey), Coffee, Food, Hiking, Nightlife, Music: broad,
  recognizable, and each maps to a category with a distinct glyph.
- **Thumbnails** are `PlaceGlyph` tiles of the closest category (`INTEREST_GLYPH`), because the app ships
  no interest images and an external image would be a real network request.
- **Rows are buttons, not `Row`:** the 1.1 `Row` primitive renders block elements (invalid inside a
  `<button>`) and only links. The picker row uses the same tokens (`surface-flat`, `type-item-title`,
  `py-item`, `gap-x-row`) and the PlaceGlyph primitive; no primitive was changed.
