# 2.2 Selection and state preservation

Built 2026-11-05 under [beta-build-rules.md](../beta-build-rules.md), lane B3 (Map). Ticket: roadmap-80.md
§4, M2 "2.2", with the founder decision and owner answer of 2026-11-05: no list or bottom panel on the map
tab on any screen size (selected-pin preview only); 2.3 is dropped. Needs 2.1 (merged on this lane).

## Contract

- **Objective:** the map tab shows the selected-pin preview only, on phone and desktop; the desktop side
  drawer moves into the separate list view. A selected pin stays visible and distinct with its preview.
  Opening a detail page and coming back restores camera, filters and selection through URL state.
  Switching to the list and back keeps filters and selection, and the list keeps its scroll position.
- **Flag:** `pilotExplore`. Off: today's Explore exactly (desktop drawer, hover-to-select from the list,
  no URL writes; the server reads only `tags` as before).
- **Out of scope:** 2.3 (dropped), native Explore (its list under the map is 8.1 work), 2.4a filter tabs.

## Acceptance

1. With the flag on, desktop map view shows no list beside the map; the results summary with a "List"
   button shows on every width, and list view hides the map and shows the list (centered column).
2. Selecting a pin keeps it as its own pin (never merged into a cluster, 2.1), pressed, with its preview.
3. The URL is kept in step with `history.replaceState` (no history spam): `at=lat,lng,zoom` (settled
   camera), `q`, `category`, `tags`, `kind`, `sel=place:<id>|event:<id>`, `view=list`. The plain map stays `/`.
4. A deep link or a reload with those parameters renders the first paint already filtered, centred and
   selected. The selection is re-read on the server with the viewer's permissions: a hidden or unknown
   record is simply not selected.
5. Back navigation from a detail page restores camera, filters, selection and view, even when the router
   reuses a server render made for the older URL (the client reads the live address bar).
6. Map ↔ list and a list → detail → back round trip keep the list's scroll position.
7. Parsing is strict: unknown categories, interests, kinds, malformed ids and out-of-range cameras are dropped.

## Choices recorded (owner can't be asked during a run; recommended option taken)

- **Replace, not push:** every pan would otherwise add a history entry and break Back.
- **The live URL wins on the client.** Next.js serves back/forward from its router cache, keyed by the
  URL that was first loaded; a lazy initial state from `window.location` makes the restore exact, and on a
  full load it equals the server's parse, so hydration matches.
- **List hover no longer selects** with the flag on: the list is no longer beside the map, so a hover
  would silently change the selection the viewer returns to.
- **`overflow-anchor: none` on the list scroller** (flag on): the browser's scroll anchoring moved the
  restored position when content above it settled (found in the browser check). It is a behaviour
  property, not a visual token.
- **Welcome marker kept while the 1.3 arrival bar shows**, so the URL still says it is the first visit.

## Changes

- `src/lib/explore/urlState.ts` (new): `parseExploreState`, `serializeExploreState`, `approximateBounds`.
- `src/app/(explore)/page.tsx`: with the flag, builds the first request from the URL (bounds, text,

- `src/components/explore/ExploreClient.tsx`: `urlState`/`initialSelected` props; live-URL initial state;
  URL writer; settled camera via `onMoveEnd`; no drawer, drawer buttons or hover-select with the flag;
  list view on desktop; list scroll memory (in memory and `sessionStorage`, guarded) with a short pending
  restore while results arrive.
- `tests/explore-url-state.test.ts` (new, 10 tests).
- `scripts/e2e.mjs`: the explore pin-label step skips cluster and stack buttons (see Test results).

Migrations: none. Dependencies: none. Shared files: none.

## Test results

- `tests/explore-url-state.test.ts` 10/10: plain URL; full round trip (**reopen after panning**: camera,
  search, category, interests, kind, selection, view); strict parsing; first-paint bounds; the real
  Explore page with a **deep link with filters** (first paint already filtered, events skipped for
  `kind=places`), a search link covering everywhere, a camera link, **back navigation** restoring the
  selection and list view, a hidden or unknown selection not restored, and flag off reading only `tags`.
- **Real browser, production demo build, port 3103, 390×844 and 1280×900** (scratch script, not committed):
  - Desktop map view: no list beside the map; the results summary and List button show.
  - Zoomed in twice, selected Little Alley Dumpling by keyboard → URL
    `/?at=39.98030,-83.00590,14.40&sel=place:…`; opened its page; Back → same URL, the same preview open
    and its pin pressed (both widths).
  - **Map ↔ list**: list at scroll 500 → Map → List → 500; list → place page → Back → `view=list`, scroll 500.
  - Deep link `/?category=food&kind=places`: Food chip pressed, filter badge 2.
  - 0 px overflow, no page errors.
  - The first runs found three real defects, all fixed before commit: Back landed on `/` (the router cache
    replayed an older render and the URL writer overwrote the address), the restored scroll was moved by
    scroll anchoring (500 → 243), and the desktop list still showed the drawer's hide button.
  - axe: one remaining finding is pre-existing and not touched here: the Filters button's name
    ("Filters") does not include its visible active-count badge (`label-content-name-mismatch`).
- `npm run check` with `TEST_DATABASE_URL` set (local PostgreSQL 16): **exit 0**. 79 files / 1,271 tests
  passed, none skipped, build OK.
- `npm run e2e` (demo, pilot flags on, port 3103): **18/19**. The pin-label step was updated because
  wide zooms now show cluster buttons first (2.1, deliberate): it now picks a single place or event pin
  and checks the same label rule. The one failure, "join an event", times out waiting for an
  `/events/<id>` link on `/events`; that page and the event page belong to lane B1 (1.5, 4.1), which this
  lane did not touch. Reported to the integrator.
