# 1.5 Quiet-utility Events tab

Built 2026-11-05 under [beta-build-rules.md](../beta-build-rules.md). Ticket: roadmap-80.md §4, M1 "1.5"
(founder decision: the Events tab is Quiet utility, the main tab for events you usually go to or have
signed up for). Lane B1 (Events).

## Contract

- **Objective:** behind `pilotFoundation`, `/events` becomes a Quiet-utility tab whose first section is
  *your* events: upcoming events you signed up for, plus events you usually go to. Flat rows grouped
  under **Today / Tomorrow / This weekend / Later**. Each row: start time on one shared left edge, title,
  venue, availability ("4 spots"). Price, Full and Cancelled are visible without expanding. Tapping the
  row expands it in place for the meeting point, the host's note and (once 4.2 lands) equipment.
- **Below your events:** the rest of the upcoming feed in the same rows and groups, paged as today, so
  discovery from this tab still works. A **Been to** view keeps today's history.
- **Off = today's screen exactly.** With `pilotFoundation` off, `src/app/events/page.tsx` renders the
  existing `EventsClient` unchanged.
- **Out of scope:** the social context line (1.4, on hold), the Readiness row (4.3), the Party poster
  (4.8), series follow (4.5b), native (`apps/mobile`).

## Choices recorded (owner can't be asked during a run; recommended option taken)

- **"Events you usually go to" rule** (roadmap: "the brief proposes a rule"). An upcoming, published
  event you have not joined is a *usual* event when, among the events you went to that already ended in
  the last 120 days (not cancelled), at least one has the **same category and either the same venue
  (`place_id`) or the same host**. Recommended over a "≥ 2 visits" threshold because the pilot has
  little history, and one return visit is already the signal people expect ("the Thursday run you
  went to"). The row says why, plainly: "Like Season opener watch party, which you went to". When
  series follow lands (4.5b), events in a series you follow or went to also count; the rule lives in
  one pure function (`src/lib/events/tab.ts`, `usualEvents`) so that is one change.
  - Only the viewer's *own* history is used. Nothing about friends is shown (no social line).
  - Candidates are the first page (100) of the viewer's visible upcoming feed, so the rule never sees
    an event the viewer cannot.
- **"This weekend"** = the Saturday and Sunday of the current week (the week ends on Sunday) in the
  viewer's time zone, when they are not already Today or Tomorrow. Everything after is **Later**.
- **Availability text:** "4 spots" when capacity is set and seats remain, "Full" when none remain,
  "Open" when there is no capacity. Price shows as "$12"; Cancelled replaces availability.
- **Host note** = the event description (the only host-entered text today). 4.1 adds newcomer fields
  and 4.2 equipment; both appear in the expanded row when present.
- **No category filter row and no "For you" rail** on the new tab: the tab is about your events, and
  Explore keeps category filtering. The rail stays on the flag-off screen.
