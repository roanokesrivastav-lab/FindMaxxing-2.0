## 2. Recommendation: split into 0.1a and 0.1b

Each half ships on its own, which the audit's batch rule requires. 0040 is uncommitted and undeployed,
so it may still be reshaped; nothing on `main` references it.

- **0.1a — durable limits for auth, reset, deletion and geocode.** 0040 keeps only the limiter, geocode
  gate and purge. Ads route switches its per-IP cap to the durable `ads` key, but `serve_ad` keeps its
  **current** billing-on-select behaviour, so ads are unchanged in money terms.
- **0.1b — signed render beacon and ad billing (F2 remainder).** The ad tables, `record_ad_impression`
  and the non-billing `serve_ad` move to **0041** (reserve it now), together with the beacon route,
  `SponsoredSlot` change and demo twin. Brief to follow after 0.1a is accepted.

If Codex rejects the split, the fallback is one batch with both halves and the full batch-1 test list;
it is larger than the roadmap's ticket size.

## 5. Acceptance criteria (0.1a)

1. `npm run check` passes: typecheck, lint, all tests, build (record the Turbopack port limitation and
   Webpack result as batch 3 did, if it recurs).
2. No symbol named `limiters` or `createMemoryLimiter` is reachable from auth, account, deletion, ads or
   geocode code. `client-errors` may keep its memory limiter; its D1 behaviour is documented.
3. Sign-in: 5 attempts / normalized email / 15 min and 20 / IP / 15 min; attempt 6 for the same email
   returns rate-limited with **zero** calls to `signInWithPassword` (spy). Distinct email+IP pairs stay
   independent; same email from different IPs shares the email cap.
4. Sign-up and reset caps are no looser than before (5/hour per IP and per email); reset keeps the
   generic response for existing and non-existing accounts.
5. Deletion password check is limited and makes zero provider calls when denied; deletion ordering is
   unchanged.
6. Geocode: request 31 within a minute from one IP returns 429 with zero `fetch` calls; concurrent
   Nominatim requests across two limiter clients admit at most one per 1.1 s; Mapbox is not gated.
7. Ads: request 121 within an hour from one IP gets `{ card: null }`; ad billing, pricing, targeting,
   Plus suppression and organic results are byte-for-byte unchanged (existing ads tests pass untouched
   apart from the limiter reset).
8. Limiter unavailable (RPC error, wrong type, missing `ABUSE_HMAC_SECRET` in Supabase mode): auth/reset/
   deletion return a controlled "unavailable" without reaching the provider; ads return no card; geocode
   returns 503. Nothing falls back to memory.
9. Stored keys are 64-hex HMACs only; no raw IP or email in any table (assert on table contents).
10. `consume_server_abuse`, `claim_geocode_provider`, `purge_server_abuse` are denied to anon and
    authenticated (function-grants inventory test passes and covers them).
11. Demo parity: the same caps, windows and wait seconds in demo mode (`consumeDemoAbuse`).
12. Two connections racing 1,000 alternating `consume_server_abuse` calls for one key never admit more
    than the cap; one race at a window boundary admits at most cap per window; two connections racing
    `claim_geocode_provider` admit at most one claim per 1.1 s. These run against real local Postgres and
    the results are recorded in the repair doc (a skipped run does not satisfy this criterion).

## 6. Required tests

- Window boundaries with an injected `p_now` / `now`: last second of a window, first second of the next,
  15-minute and 60-second windows.
- Multi-key check-before-reserve: an email at its cap does not consume the IP budget, and vice versa.
- Real route/action calls (not helpers) for sign-in, sign-up, reset, deletion, geocode and ads, with
  provider spies asserting zero calls on denial.
- `trustedClientIp`: header unset, wrong header name, chains (`a, b`), ports, IPv6, IPv4-mapped IPv6,
  garbage — plus the D1 behaviour for each.
- Storage outage path for each caller (RPC returns error).
- Purge: expired rows removed, live rows kept, bounded batch.
- Two separately constructed `createDurableLimiter` clients against one PGlite database share one budget
  (sequential), plus the D2 two-connection races on real Postgres.
- Harness self-test: refuses a non-localhost `TEST_DATABASE_URL`; drops its throwaway database afterwards.

## 8. 0.1b outline (separate brief later)

Migration 0041: `ad_beacon_nonces`, `ad_client_daily`, `record_ad_impression`, non-billing `serve_ad`.
