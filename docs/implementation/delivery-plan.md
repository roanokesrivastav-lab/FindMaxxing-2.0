# Delivery order and checkpoints

The complete phase table and all feature decisions are in [the proposed roadmap](../proposed-roadmap-2026-11-11.md#recommended-sequence). Numbered prompts are in [the batch pack](../briefs/fable-5.2/README.md). This index does not create parallel-agent authorization.

1. **00 Baseline/spec amendments:** reuse foundations, verify a clean candidate, narrow the high-risk series/admission contract without waitlists, and reconcile dependency exclusions.
2. **01 Onboarding:** six rows/More/Skip, faithful first-map filters and first useful save.
3. **02 Events:** editorial details, series/host tools, series page, relevant notifications, optional poster and quiet personal Events tab.
4. **03 Places/library:** photo-first evidence, independent occasion notes, private-photo contract, richer owner-only saves, bulk/undo/export/picker.
5. **04 Routing foundation:** walking adapter/fake and pure deterministic feasibility validator.
6. **05 Explore:** clustering, preview-only layout, honest time/travel/activity/Has room filters and mode-aware pins. No restore work.
7. **06 Outings:** membership/invites/shortlist/votes/constraints/lock/anchor after the verified Must Events subset.
8. **07 Shared itinerary:** persisted plan/verdict, invalidation, second-member reopen and versioned editing.
9. **08 Local/memories:** flash maps, expiring reports, explicit helpful feedback, R4 spec and privacy-safe weekly recap.
10. **09 Native:** selected Explore/admission/outing/invite/itinerary parity and genuine device evidence; no offer UI/restoration.
11. **10 Journey/release:** integrated journey, metrics, exact candidate/migrations and separate authorized platform gates.

Independent routing foundations may move earlier when prerequisites are verified. Metrics begin with first-save/outing work rather than waiting until the final phase. Native admission compatibility must be coordinated before a conflicting server change is released.

## Review checkpoints

- After onboarding: five newcomers, first wrong tap, prediction vs result, time to useful save.
- After Events/places/Explore: hosts create real permitted test sessions; inspect normal/full/cancelled/empty/no-photo/denied states.
- After itinerary: three friends complete shortlist → lock → anchored plan; record decision time and organizer effort.
- Before release: inspect Must traceability, privacy and separate web/iOS/Android evidence. A missing platform result is NOT VERIFIED.

For unattended work, write the checkpoint bundle and continue only when required reviews/verification permit it. No scheduled reminder or calendar date was requested; follow-up happens when the founders return.
