# Approved interface direction

Use [founder decisions](../founder-decisions.md), existing `src/components/ui` primitives and `src/app/globals.css`; do not invent a new theme. The [self-contained call review](../founder-call/2026-11-11/README.md) gives dated screenshots and illustrative target layouts.

- Local editorial: event detail/features. Quiet utility: Events and comparisons. Photography leads when available; a complete glyph/fallback composition is required without it.
- Raised surface means floating selection, flat means comparable rows, inset means a tip/note. Preserve one alignment edge, shared spacing/type roles, warm paper colors and current fonts.
- Map tab: selected-pin preview only at all widths, separate result mode. Co-located records cycle 1-of-N. Do not implement full camera/state restoration yet.
- Filters: useful time/area/activity options, Has room default availability. Honest route/availability unknowns and explicit empty-state widening; never silently relax a selected filter.
- Event cards: readiness normally, optional host poster. No date-block tile; visible price/full/cancelled. Event detail has logistics and host-written newcomer help near its primary action.
- Place page: photo first, supporting evidence below, rating with count, distinct actual friends/community reviews. No summaries or match scores. Generic freshness is Later; do not use illustrative confirmation dates as actual facts.
- All new flows: loading, empty, error, busy/disabled, denied, long text, missing image, large text, keyboard and labeled actions. Do not infer that an unavailable screenshot proves a design works.

Target previews are presentation samples, not approved schema or claims of completion. Use screenshots for context and the written acceptance criteria for implementation.
